================================================================================
KEY DECISIONS LOCKED IN
================================================================================

1. SINGLE DOMAIN EVENT → SINGLE COMMUNICATION EVENT
   - One-to-one mapping (no aliasing)
   - Prevents confusion and duplicate routing
   - Makes debugging straightforward

2. REGISTRY AS SOURCE OF TRUTH
   - Downstream components read from registry, not hardcode
   - Changes go through registry first
   - Reduces bugs and drift

3. NO BYPASSES ALLOWED
   - Every communication flows through: Event → Subscriber → Runtime → Provider
   - No direct notify() calls (except in NotificationDomainSubscriber)
   - No direct provider calls (always through provider adapter)
   - Ensures complete audit trail

4. CHANNEL SELECTION PER AUDIENCE
   - Each audience gets different channels for same event
   - Applicant → email, internal
   - Org admin → telegram, internal
   - Staff → email/telegram/internal
   - Prevents over-notification

5. RETRY POLICIES CONSISTENT
   - Critical events: max 5 attempts
   - High: max 5 or 3 depending on urgency
   - Normal: max 3
   - Exponential backoff for all

6. ALWAYS ASYNC
   - No blocking sends
   - All notifications async (fire and forget)
   - Ensures business logic never waits for delivery

7. NEW DOMAIN EVENTS FOR MANUAL COMMUNICATIONS
   - `communication.manual_send` for composed emails
   - `admin.alert.*` for system alerts
   - Treats manual communications as business events
   - Enables full audit trail

WHAT'S NOT IN THIS REGISTRY

These are future extensibility points:

1. SMS/Twilio
   - Can be added as new channel
   - No code changes needed (channel added, provider adapter created)

2. WhatsApp
   - Currently stubbed in provider adapters
   - Registry can add as channel once provider ready

3. Push Notifications
   - New channel type
   - New provider adapter
   - Registry entry per event

4. Scheduled Communications
   - Registry can add scheduled: true/false
   - Scheduler logic separate from registry

5. AI-Generated Messages
   - Registry can mark templates as ai_generated: true
   - Template engine handles rendering

6. Personalization Rules
   - Registry can add per-audience personalization
   - Can reference user/organization fields
