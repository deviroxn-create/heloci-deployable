## ROOT CAUSE (EVIDENCE-BASED)

### Primary Cause: Audience-Prefixed Keys Never Created

**Location**: `lib/notifications/template.service.ts`, line 245

**Function**: `syncTemplatesFromSettings()`

**Evidence**:
- Database query: 0 records match pattern `{audience}.{event}.{channel}`
- Code inspection: Only `{eventName}-{channel}` format created
- Planner expectation: Generates audience-prefixed keys
- Result: 100% mismatch

### Secondary Cause: Planner Assumes Keys Exist

**Location**: `lib/notifications/runtime/template-resolver.ts`, line 24

**Function**: `resolveTemplateKey()`

**Evidence**:
- Code: Returns `${audiencePrefix}.${eventKey}.${channel}`
- Database: No such keys exist
- Fallback: Catches misses, but masks issue

## DELIVERY SUCCESS EXPLANATION

**Why notifications work despite 100% key mismatch:**

```
Planner generates: applicant.user-registration.email
  ↓
TemplateService.getPublishedTemplateByKey() called
  ↓
Lookup #1: findFirst where name = "applicant.user-registration.email"
  Result: ❌ NOT FOUND
  ↓
Fallback #1: Parse key, extract event=user_registration, channel=email
  ↓
Lookup #2: getPublishedTemplate("user_registration", "email")
  Result: ✅ FOUND ("Welcome Email")
  ↓
Delivery: ✅ EMAIL SENT (with generic template)
```

**Pattern**: 13 cases find generic fallbacks, 63 cases use hardcoded defaults
