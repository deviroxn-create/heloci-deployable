# Working Structure: Milestone-Driven Development

---

## The Pattern

Every milestone follows this structure:

### 1. Current Goal
What are we working on? Why does it matter?

### 2. Scope
What IS included? What is NOT included?

### 3. Deliverables
What files/tests/documentation must we create?

### 4. Exit Criteria
Objective conditions for being "done."

### 5. Next Prompt
The exact prompt to begin the next milestone (provided at the end).

---

## Benefits

✅ **No ambiguity** — Everyone knows exactly what's being done  
✅ **No drift** — Scope is clear, prevents feature creep  
✅ **No guessing** — Exit criteria defined before starting  
✅ **Clear handoff** — Next milestone ready immediately  
✅ **Easy to reference** — Can look back and see what was done  

---

## How to Use

### Starting a Phase
1. Read the phase specification document
2. Review "Current Goal," "Scope," "Deliverables"
3. Begin work
4. Reference exit criteria frequently

### Completing a Phase
1. Verify all exit criteria are met
2. Generate final report
3. Read "Next Prompt"
4. Begin next phase

## Key Rules

1. **Every milestone ends with "Next Prompt"**
   - No guessing what comes next
   - New milestone is clearly defined

2. **Scope is explicit**
   - "What IS included" is stated
   - "What is NOT included" is stated
   - Prevents feature creep

3. **Exit criteria are objective**
   - Not subjective ("feels good")
   - Measurable ("all tests pass")
   - Verifiable ("report generated")

4. **No phase lasts more than 2 weeks**
   - Short, focused iterations
   - Easy to stay on track
   - Regular progress checkpoints
