  - Dynamic event name transformation in lib/workflows/workflow-engine.ts (130)
  - Registry lookups bypassed in multiple places

IMPACT: Registry authority compromised by undocumented events and hardcoded logic.


CLAIM #4: "Zero silent drops - all events are either delivered or logged"

ACTUAL FINDING: ⚠️ PARTIALLY TRUE

  - Direct notify() calls: ⚠️ No registry validation (could be unregistered)
  - Custom_email event: ❌ Not in registry, no validation

IMPACT: Registry validation not universal across all notification paths.


CLAIM #5: "Zero duplicate subscribers - no multi-subscription"

ACTUAL FINDING: ❌ POTENTIAL VIOLATION
  - NotificationDomainSubscriber: Single registration guaranteed
  - RuntimeSubscriber: Code ready to be registered
  - No mechanism preventing RuntimeSubscriber registration in Phase C/D
  - If both registered: dual-processing of same event

IMPACT: Dual-subscription possible in Phase C/D.
